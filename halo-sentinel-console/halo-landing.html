    Four layers, one direction

    Signals flow in. Nothing flows back out to your network except an action a person approved or a policy pre-approved.

    1. Ingest

      Endpoint agents, cloud logs, SIEM, scanners and firewall alerts are normalized, de-duplicated and merged into one case.

      Queue and log shipper

    2. Context

      Adds asset criticality, identity history, threat intel and past incidents, so a spike is judged against what is normal.

      Database, no AI yet

    3. Reason

      The model explains what likely happened, scores severity and confidence, and recommends an action, citing the log lines behind each claim.

      Sandboxed model call

    4. Act

      An analyst approves, edits or rejects. A policy engine lets only narrow, reversible actions run automatically. Every step is logged.

      Human approval and audit log

    Built so a bad answer cannot do damage

    Log text can be written by an attacker, so the system treats it as data and never as instructions.

    Recommends, never decides

    Model output goes to a person. Automatic actions are limited to pre-agreed, reversible steps, such as isolating a non-critical host.

    Every claim has evidence

    If H.A.L.O. cannot point to the log line behind a statement, it does not make the statement.

    Prompts are logged and sanitized

    Each prompt and response is recorded for review. Raw log content is escaped before it reaches the model, to block prompt injection.
